## Problema

Una aplicación de tareas puede resolverse solo con una interfaz web, pero exponer las mismas operaciones a agentes de IA añade una segunda superficie que tiende a duplicar reglas y persistencia. El proyecto aborda ambas entradas sobre una única capa de negocio.

## Rol

Proyecto personal. Diseñé y desarrollé la interfaz, el servidor MCP, la autenticación, las pruebas y la documentación de arquitectura.

## Decisiones

1. **Arquitectura dual con una sola lógica.** La interfaz usa Next.js 16 con App Router, React 19 y Server Actions; el servidor MCP corre sobre SQLite. Ambos comparten la capa de negocio con Prisma y validación Zod.
2. **Cinco herramientas CRUD para agentes.** El servidor expone creación, lectura, actualización y eliminación de tareas, además de filtros por estado, búsqueda paginada y actualización automática de la fecha de culminación.
3. **Tokens por usuario con revocación.** La autenticación usa Better Auth y los tokens MCP se guardan con hash SHA-256, con revocación inmediata.
4. **Calidad verificable.** La cobertura incluye pruebas unitarias, de integración y E2E con Vitest y Playwright, junto con una documentación de arquitectura interactiva y autocontenida.

## Resultado

La aplicación combina una interfaz web y un servidor MCP que operan sobre la misma persistencia. Las cinco herramientas CRUD, los filtros, la búsqueda paginada y la actualización de la fecha de culminación quedan cubiertos por pruebas. El repositorio está disponible; la demo pública sigue pendiente.
